# MASBench T3 四题能力诊断预算提案

2026-11-25，Asia/Shanghai。四个冻结开发家族、base 主提示族、protocol 辅助、Full／No-A2A 配对。16 个 episode，每个最多六个总发言机会。另计两个合成预检。审批状态和实测证据以最新任务报告为准。

| 项目 | 拟冻结硬上限与依据 |
| --- | --- |
| 模型与窗口 | Ollama 0.11.11、固定 `qwen2.5:7b` digest、固定模板/helper、实际窗口 16384，单并发。启动前的活动服务仍为 1024，实际长窗口需单独启用和核验。 |
| 数量与 Token | 最多 96 个任务生成＋2 个合成生成。每个请求固定预留 **512 输出**，累计 **50,176 输出 tokens**。完整输入最多 `16384−512=15872`，合计硬上界 **1,555,456 输入 tokens**。实际 usage 对账，超窗、超时、缺 usage 和截断分别记明。所有已预留的失败额度不退款。 |
| 时间 | 建议每次准备与绑定 ≤150 秒、其中渲染≤120 秒，生成≤180 秒，单次清理≤40 秒。`98×(150+180)=32,340 秒`；18 次最多 40 秒的清理计 720 秒，**整轮 34,800 秒（9 小时 40 分）**包含启动、切换和审计收尾余量。这是串行硬上界，实际耗时仍未知。原 6000 秒预算平均每次约 61 秒，已低于 T2 单条所测的 85.21 秒。 |
| 控制与资源 | 每次均校验完整渲染、runtime identity、runner 生命周期。计划 98 次渲染、312 次常规 GET、108 次清理 GET、18 次卸载，计入 T3 硬预算。CPU 2 核，Driver RSS 2 GiB，服务进程树 RSS 与 GPU 采样各 16 GiB。单并发、无自动重试。 |
| 存储 | 建议原始请求、响应、通信明细及持久预算账本放个人 HDD，项目 SSD 仅放运行登记、索引与恢复控制，新增分别 ≤1 GiB／≤32 MiB。将落盘余量纳入准入，预留独立控制日志空间，关闭新派发后仍留有原始证据与卸载空间。HDD 按允许根目录、独占新目录、文件 SHA 和读回证明核验；SSD/HDD 协作流程待准入合同。 |

正式销项前，先锁定所有 episode 和配对顺序，确认 task、synthetic 各用独立额度。一次性记录实际运行身份。两条件复用同一初始私有视图、Prompt 及调度设置。保留原始发送、接收、下一请求中的消息可见性证据。独立评分在任务运行完成后读取 gold，运行中使用私有视图。所有已启动的 timeout、解析、格式及截断失败主分母计零，未开始单列，任何缺配对视为未完成。

工程合同通过并另行批准具体预算后才发送真实四题。科学继续阈值沿用预先约定的主提示族，至少两个不同家族在 Full 下 EM 正确，且至少一配对 Full−No-A2A F1 正差有对方下一请求已收到消息的证据。四题为开发可行性诊断；D1 文章隔离、正式样本效应与统计功效维持原关卡。 [T2 实测](../reports/masbench_t2_context_acceptance_2026-11-25.md) · [D1 决定](../benchmarks/masbench_d1_evaluation_decision_2026-11-16.md)
